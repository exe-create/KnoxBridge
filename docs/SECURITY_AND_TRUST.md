# Security and trust

Java modules execute with the game's JVM permissions. KnoxBridge is not a Java sandbox. Approval informs the player and keys trust to the actual JAR's SHA-256 digest; it cannot make malicious Java code safe.

The Windows setup verifies the embedded player archive and its bundled runtime JAR/bootstrap DLL against included SHA-256 sidecars before installation. These checks detect accidental corruption or inconsistent package contents; they are not a code-signing certificate, publisher authentication, malware scan, or guarantee that Windows Security will accept an unsigned installer. Stop if antivirus reports a threat. Do not restore, run, or whitelist a flagged file.

Unknown and changed JAR hashes are blocked by default. The Bridge Workshop Lua screen displays JARs found beneath enabled PZ mod roots and collects exact-hash allow/deny choices in the user's `Zomboid/Lua/KnoxBridge` directory. On the next full launch, the Java agent imports once-only or remembered decisions into `%USERPROFILE%\Zomboid\KnoxBridge\trust.properties` before checking modules. If the list or decision file is missing or invalid, unknown JARs stay blocked. A changed binary has a different hash and requires a new decision.

The screen displays module name and declared `author` from `mod.info` as unverified claims, plus module ID, version, and full JAR SHA-256. The selected row is highlighted, the details identify the selected JAR, and Allow/Deny actions apply to that selection. It shows unsupported enabled-mod JARs too; those remain blocked and cannot be allowed until the author adds a valid KnoxBridge descriptor/API entry point. The full-screen gate appears at the PZ main menu before world entry. Decisions apply on the next launch because Bridge discovery/loading happens before PZ's Lua main-menu UI, and late module loading can miss required early instrumentation targets.

**Remember next choice** applies only to the next successfully saved decision, then resets. Without it, the queued choice applies for one PZ launch to that exact hash (including any enabled modules with the same JAR hash); the next launch resumes the previous remembered decision, if one existed. A remembered choice persists for that exact hash until the JAR changes or the player changes the choice. A restart is needed only when the effective loaded module set changes. The player must confirm quitting to desktop, then start PZ again through Steam; KnoxBridge does not automatically relaunch the game. If the review UI or file handoff fails, unknown modules remain blocked; report the issue rather than bypassing it. These screen and restart interactions still need live Build 42 testing. Author signing, signature verification, and changed-signed-build policy are not implemented. Never distribute private signing keys in this project or a module.
